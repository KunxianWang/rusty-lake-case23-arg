# 《锈湖档案：23号案》完整制作流程与验收表 V1

> 目标：把现有剧情、搜索流程与工程规范制作成一款 60—90 分钟、单 HTML、可离线打开的完整网页 ARG。  
> 交付：`src/index.html`；不使用后端、外部 API、GPT Sites 或构建框架。  
> 发布：未经用户明确指示，不部署、不上传 GitHub。  
> 状态标记：`未开始`、`进行中`、`已完成`、`已验收`。

## 1. 制作原则

| 原则 | 本项目的执行方式 |
|---|---|
| 三根玩法支柱 | 浏览档案、主动检索、重建关系 |
| 核心 20% | 搜索框、档案阅读、谜题提交、进度保存优先于装饰动画 |
| 7—10 分钟节奏 | 每阶段引入一种新档案形式、谜题形式或解释反转 |
| 确定性谜题 | 相同证据与输入始终得到相同结果，不使用随机答案 |
| 面包屑提示 | 方向提示 → 材料提示 → 操作提示，失败不扣进度 |
| 无惩罚错误 | 错误说明“错在哪里”，不锁页面、不删除证据、不毁坏存档 |
| 范围控制 | 先保证 31 份核心档案与 8 个谜题完整，再增加音频和高级动效 |
| 单一真相边界 | 可确认人物关系与记忆机制，不给劳拉指定原作未确认的唯一凶手 |

## 3. 每一阶段的固定生产循环

| 步骤 | 产出 | 完成定义 |
|---:|---|---|
| 1 | 内容装配 | 每份档案有标题、来源、年代、可信度、正文、项目组注释与关键词出处 |
| 2 | 搜索接线 | 每个标准词有别名、前置条件、结果状态、噪声结果与提前猜词处理 |
| 3 | 谜题接线 | 目标、操作、确定答案、两条公平线索、错误分类与三级提示齐全 |
| 4 | 理论变化 | 明确玩家进入前相信什么、哪份证据改变它、更新后的当前问题 |
| 5 | 状态验证 | 搜索、打开、固定证据、解谜、阶段变化均可保存并刷新恢复 |
| 6 | 黄金路径 | 从阶段入口按正常玩家路径走到阶段结尾，没有死路或必须猜作者意图的跳跃 |
| 7 | 边界路径 | 测试提前猜词、别名、错序、重复提交、关闭弹层、移动端与禁用存储 |

## 5. 最终发布前不可妥协项

- 玩家始终是匿名外部调查者，网站不会认识、追踪或选择玩家。
- 项目组只使用有限、理性的档案语言，不成为全知叙述者。
- 搜索结果首次发现新页面；“已发现档案”不泄露未发现标题。
- `23-BLACK` 在条件不足时始终只是索引占位。
- P8 检查证据结构，不把关系问答降级成记名字。
- 档案冲突代表记忆版本并存，不等于给出一个隐藏的“唯一正确死亡画面”。
- 游戏在没有音频、外部图片、网络或浏览器存储时仍可完成主线。
