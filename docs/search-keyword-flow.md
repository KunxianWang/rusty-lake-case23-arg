# 《锈湖档案：23号案》搜索关键词与具体游戏流程 V1

> 文档性质：搜索玩法、页面解锁和调查顺序的权威执行规范。  
> 适用范围：后续网页文案、搜索索引、谜题、状态管理、提示系统和测试用例。  
> 优先级：涉及“玩家从哪里得到关键词、搜索后看到什么、下一步如何前进”时，以本文为准；  
> 涉及原作人物关系与结局时，以 `complete-story.md` 和正史事实表为准。

---

## 0. 使用规则

后续制作必须遵守以下约束：

1. 不得新增主线必搜关键词而不更新本文。
2. 不得更改本文规定的标准关键词、结果档案和前后依赖而不更新本文。
3. 每个必搜关键词必须在玩家此前能够访问的材料中出现。
4. 每个关键推理至少由两份可发现证据支持。
5. 新档案第一次出现必须由搜索触发，不能通过“相关页面”直接泄露。
6. “已发现档案”只能返回玩家已经打开的材料，不能展示未发现标题。
7. 玩家提前猜中后期词时，可以看到索引占位，但不能提前阅读完整内容。
8. 搜索错误没有惩罚，不限制次数，不清空进度。
9. 玩家始终是外部调查者；搜索结果不得声称网站认识、追踪或选择了玩家。
10. 劳拉之死不得通过任何关键词搜索得到一个本作虚构的唯一凶手。

本文规定：

- **29 个主线搜索节点**；
- **9 个可选搜索节点**；
- **31 份核心档案**；
- **4 份辅助检索页**；
- **6 份隐藏档案**；
- **8 个必要谜题门槛**；
- **1 个主结局与 1 个可选余韵页面**。

## 1. 标识与状态约定

### 1.1 标识

| 前缀 | 含义 |
|---|---|
| `K` | 主线关键词 |
| `O` | 可选关键词 |
| `D` | 核心档案 |
| `F` | 辅助检索页或分类残页 |
| `H` | 隐藏档案 |
| `P` | 必要谜题 |
| `S` | 剧情阶段 |
| `T` | 玩家当前理论 |

### 1.2 页面可见状态

每个搜索结果只能处于以下四种状态之一：

| 状态 | 玩家看到的内容 |
|---|---|
| `hidden` | 搜索不返回该条目 |
| `stub` | 只显示标题、年代、来源和“附件位置尚未确认” |
| `available` | 可以打开完整档案 |
| `conflicted` | 可以打开两个或多个互不兼容的版本 |

### 1.3 搜索状态变化原则

- 玩家还不知道某个后期词但提前猜中：通常返回 `stub`。
- 玩家已经从材料中取得该词，但缺少谜题条件：返回 `stub`，并说明缺少来源链。
- 玩家满足前置条件：变为 `available`。
- 后期需要表达记忆版本冲突：变为 `conflicted`。
- 页面从 `stub` 变为 `available` 时，搜索历史保留原记录并加注“附件已恢复”。

## 2. 搜索引擎输入规则

### 2.1 自动标准化

搜索系统必须自动处理：

- 英文字母大小写；
- 全角和半角字符；
- 多余空格；
- 姓名中的句点；
- 连字符与空格；
- 姓名顺序；
- 中文名与英文名；
- 常见拼写错误；
- 年份放在关键词前或后。

例如以下输入等价：

- `A. Vanderboom`
- `A Vanderboom`
- `a vanderboom`
- `Vanderboom A`
- `阿尔道斯 范德布姆`

### 2.2 组合搜索

组合搜索不要求固定词序：

- `Robert Hill 1972`
- `1972 Robert Hill`
- `Bob 1972`

三者均命中 `K13`。

### 2.3 编号搜索

编号允许忽略连字符和空格：

- `RL-23`
- `RL23`
- `RL 23`

但不能允许过度模糊。例如只输入 `23` 时，应返回多个普通结果，不能直接打开 `23-BLACK`。

### 2.4 搜索结果数量

- 精确姓名或编号：1—4 条结果；
- 单一年份：大量普通结果，不直接推进主线；
- 宽泛词如 `lake`、`death`、`black`：返回噪声档案和分类说明；
- 精确组合词：优先返回目标档案；
- 每页最多显示 7 条，避免通过结果数量暴露正确答案。

### 2.5 “无结果”反馈

第一次失败：

> 未找到完全匹配的公开记录。  
> 已识别内容：`Vanderboom`

连续两次接近：

> 该名称存在跨年代记录。添加年份或档案编号可能有助于缩小范围。

玩家停滞 90 秒：

> 项目组整理建议：部分历史记录只使用姓名缩写。

不得直接显示下一条标准关键词。

# 5. 具体游戏流程

## S0：序章与搜索教学

### 玩家初始状态

- 可访问：D01、D02、D03；
- 搜索历史为空；
- 已发现档案：3；
- 当前问题：“第六份附件是什么？”；
- 当前理论T0：“这是一宗可能与感情纠纷有关的普通死亡案。”

**性质：** 主线必搜、P1教学谜题。  
**标准输入：** `CASE 23`

### 可接受输入

- `case23`
- `case 23`
- `23号案`
- `案件23`
- `RL CASE 23`

### 玩家从哪里获得

1. D02标题下方的红色印章：`COUNTY CASE 23`；
2. D03新闻剪报底部的排版标记：`Police reference: Case 23`；

### 输入后获得

搜索结果页显示“23号案完整索引”：

- D02由公开摘要升级为扩展索引；
- 显示附件总数6、已定位5；

  - Laura Vanderboom；
  - Robert Hill；
  - Detective D. Vandermeer；
- 显示内部档案编号字段`RL-23`，但暂时不能打开现场批次；

### 页面必须包含的新线索

- `Laura Vanderboom`
- `Robert Hill`
- `Dale Vandermeer`
- `RL-23`

### 状态变化

- `P1 = solved`
- `K02/K03/K04 = discoverable`
- 当前问题增加：“三份公开记录中的死亡时间为什么不同？”
- 搜索历史开始记录。

### 卡关提示

1. “案件编号同时出现在新闻页和警察印章上。”
2. “搜索完整编号，而不是只搜索数字。”

## K02：`Laura Vanderboom`

**性质：** 主线必搜、人物搜索教学。  
**标准输入：** `Laura Vanderboom`

- `Laura V`
- `Vanderboom Laura`
- `劳拉 范德布姆`
- `劳拉·范德布姆`

单独输入`Vanderboom`返回家族姓氏噪声，不直接完成K02。

### 玩家从哪里获得

1. D02受害者字段；
2. D03新闻标题和第一段；
3. K01扩展索引。

### 输入后获得

结果一：D04尸检摘要。

- 记录发现时间与新闻不一致；
- 眼部存在无法解释的黑色沉积；
- 档案页脚出现批次号`RL-23`；

- 一幅未完成的湖景画；
- 与哈维的生活照片；
- 写给鲍勃但没有寄出的便笺；
- 便笺使用姓名`Bob`，为K03提供别名；
- 照片背面写着住所编号和1971年日期。

### 页面必须包含的新线索

- `Bob Hill`
- `Harvey`
- `RL-23`
- “同一人的记录存在两个发现时间”

### 状态变化

- `D04/D07 = discovered`
- 劳拉从“新闻死者”变成有生活细节的人；
- T0受到第一次削弱：材料不足以证明鲍勃涉案。

### 卡关提示

“案件摘要中的姓名字段可以直接搜索。”

- `seen_keywords`：玩家已打开包含该关键词的来源页；
- `searched_keywords`：玩家已经实际输入过；
- `discovered_documents`：可以在“已发现档案”中返回；
- `pinned_evidence`：最终报告可选证据；
- `hint_levels`：每个关键词和谜题独立记录提示级别；
- `search_history`：保留原始输入和标准化后的命中项；
- `secret_flags`：不显示为进度百分比；
- `ending_complete`：控制K29和O09。

# 13. 首轮测试验收标准

邀请不知道设计答案、但可以不知道Rusty Lake原作的测试者完成一次黑盒测试。

必须达到：

- 80%以上测试者能在5分钟内完成K01；
- 70%以上测试者无需明确答案提示完成S1；
- 没有测试者把D10理解成“存在一辆秘密运输车”；
- 大多数测试者在S2结束时不再把Bob视为主要凶手；
- 测试者能说明Laura与William的关系，但不会说“Laura只是William”；
- 测试者能把兔面人物标为高度相关，而不是被迫确认绝对身份；
- 测试者能理解`23-BLACK`为何不能提供唯一死亡版本；
- 任何卡关都能通过三级提示恢复；
- 不看攻略也能进入D30；
- 不完成可选秘密也能正常结案。

如果某个必搜词有超过30%的测试者无法发现，应优先调整关键词来源或页面呈现，而不是把答案直接写进提示。
